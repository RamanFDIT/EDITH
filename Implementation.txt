E.D.I.T.H. Security & Performance Hardening
Implements all 8 issues identified in 
SecurityPlan.md
: 4 security vulnerabilities and 4 performance bottlenecks.

User Review Required
IMPORTANT

S1 — Command allowlist: The 
executeSystemCommand
 function currently lets the LLM run any shell command. The fix introduces a strict allowlist of safe commands (dir, 
ls
, echo, type, 
cat
, whoami, hostname, ipconfig, netstat, ping, systeminfo, tasklist, git, node, npm, python, pip). Arbitrary commands from the LLM will be blocked. If your workflow relies on the LLM running unrestricted commands, this will be a breaking change. Let me know if you'd like to customise the allowlist.

WARNING

S2 — Encrypted store: OAuth tokens and API keys will be encrypted using Electron's safeStorage API (DPAPI on Windows). This means the existing plaintext edith-config.json will not be readable on a different machine. First launch after this change will auto-migrate existing plaintext tokens.

Proposed Changes
Security: Command Injection Hardening
[MODIFY] 
systemTool.js
executeSystemCommand
: Replace raw 
exec(command)
 with:

A static allowlist of permitted base commands
Parse the first token of the command to check against the allowlist
Use child_process.execFile with an argument array (prevents shell metacharacter injection via &, |, ;)
Log blocked commands for auditing
openApplication
: Already uses safeAppName regex — improve by:

Switching the final 
exec(command)
 to execFile('powershell', [...args]) to avoid shell interpretation
Validate safeTarget against a URL/filepath pattern before passing to Start-Process
Security: Encrypted Secret Storage
[MODIFY] 
store.js
Add a SecureStore wrapper class around electron-store that:
Defines a list of sensitive keys (OPENAI_API_KEY, ELEVENLABS_API_KEY, all oauth_* keys, etc.)
On set(key, value): If safeStorage.isEncryptionAvailable(), encrypt sensitive values with safeStorage.encryptString() before writing
On 
get(key)
: Decrypt on read with safeStorage.decryptString()
Falls back to plaintext if safeStorage is unavailable (non-Electron / CI contexts)
Add an auto-migration routine: on first load, if existing values are plaintext strings (not Buffers), encrypt them in place.
[MODIFY] 
envConfig.js
Update the store.get() calls for OAuth tokens to use the new SecureStore API (the interface is the same, so changes are minimal — just ensure Buffer decryption is wired up).
Security: Path Traversal Prevention
[MODIFY] 
server.js
Change the fileUpload multer 
filename
 callback from:
js
cb(null, `upload-${Date.now()}-${file.originalname}`)
to:
js
import crypto from 'crypto';
const uuid = crypto.randomUUID();
const ext = path.extname(file.originalname).replace(/[^a-zA-Z0-9.]/g, '');
cb(null, `upload-${uuid}${ext}`);
Keep file.originalname in the response JSON for the frontend, but never use it as a filesystem path.
Security: Strict CORS
[MODIFY] 
server.js
Replace app.use(cors()) with:

js
app.use(cors({
  origin: ['http://localhost:5173', 'http://localhost:3000', 'app://./'],
  methods: ['GET', 'POST'],
  credentials: true,
}));
Performance: Agent Caching (Singleton)
[MODIFY] 
agent.js
Replace 
getOrCreateAgent(tools)
 with a cached version:
Use a Map<string, CompiledAgent> keyed by sorted tool-name signature
On first call with a new signature, compile the agent and cache it
On subsequent calls, return the cached agent
The system prompt is injected per-request via stateModifier, so the timestamp stays fresh
The comment on line 963 says "Don't cache agents" — this will be reversed. The system prompt's timestamp is already computed per-request through getSystemPrompt(), but we need to ensure it's passed as a message prepend, not baked into the cached agent. Restructure to pass stateModifier as a function (LangGraph supports this).
Performance: Enhanced Fast-Pass Intent Classification
[MODIFY] 
agent.js
Expand the KEYWORD_MAP with ~30 additional high-frequency keyword patterns per category to increase fast-pass hit rate from ~60% to ~90%.
Add regex patterns for common natural language phrasing (e.g., "do I have any .*(?:meeting|event)" → calendar).
These are zero-cost CPU-only checks that avoid the LLM round-trip.
Performance: TTS Audio Queue
[MODIFY] 
server.js
Replace the fire-and-forget 
generateAudioChunk()
 pattern in both /api/ask and /api/voice with an ordered queue:
Push sentences into an array with a sequence number
Process the queue with a sequential async loop
Write the audio SSE event only after the chunk is generated AND all prior chunks have been emitted
This ensures audio SSE events arrive at the frontend in grammatical order.
Performance: Chat History Debounced I/O + Sliding Window
[MODIFY] 
agent.js
Debounced writes: Replace 
saveToDisk()
 (called on every 
addMessage
) with a debounce using a timer:
Set a 2-second debounce: if another write comes within 2s, reset the timer
Prevents rapid sequential file writes during a streaming response
Sliding window: The existing MAX_HISTORY_MESSAGES = 30 already limits LLM context. Add disk-level pruning:
When the on-disk history exceeds 200 messages, prune the oldest messages (keep last 200)
This prevents the JSON file from growing indefinitely

Anti-Hallucination Protocols
- **[MODIFY] All Tool Modules**: Standardize "No Results" and "Error" responses to return descriptive objects instead of empty values, forcing the LLM to acknowledge data absence.
- **[MODIFY] systemPrompt.js**: Implement "Receipt Protocol" — the AI must cite real tool outputs (IDs, links) in its response.
- **[MODIFY] agent.js**: Implement "Freshness Guard" — a system message injected before each query to prevent history confusion.
- **[MODIFY] agent.js**: Enhance `sanitizeHistoryForTools` to prune potentially confusing past tool outputs.

Verification Plan
Manual Verification
Since this project has no test suite, the changes will be verified manually:

Start the server with node server.js and confirm no crashes or import errors
CORS test: Open a browser tab to http://example.com and try fetch('http://localhost:3000/api/history') in DevTools — it should be blocked by CORS
File upload test: Upload a file via the frontend and check that the saved filename in the edith-uploads folder is a UUID, not the original name
Command injection test: Ask the agent to run a benign command like node --version (should work) and then something dangerous like rm -rf / (should be blocked with a logged warning)
TTS ordering: Ask a multi-sentence question and verify audio chunks play in order
Agent caching: Check server logs for "Reusing cached agent" messages on repeat queries to the same tool category
Anti-Hallucination: Ask for a non-existent Jira ticket; verify "not found" response
Receipt Protocol: Create a calendar event; verify the response includes the real Event ID
Freshness Check: Ask for a meeting at 2pm, then immediately ask for another; verify it doesn't confuse the two
TIP

I'd appreciate your suggestions on any additional manual tests you'd like to see, especially around the encrypted store migration.
